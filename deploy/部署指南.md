# Job Copilot 阿里云部署方案（Ubuntu + systemd + Nginx，含数据迁移）

> 适用：阿里云 ECS，Ubuntu 22.04 / 24.04，**只有公网 IP、暂无域名**，数据需要从开发机迁到服务器。
> 路线：宿主机手工部署（uvicorn + systemd + Nginx），不用 Docker。Docker 路线见[附录 A](#附录-a-docker-路线)。
> 预计耗时：首次 60–90 分钟（含数据迁移与验收），后续发布 2–3 分钟。

## 一、方案总览

### 架构

```text
浏览器
  │  http://<公网IP>/   （80 与 8080 双入口）
  ▼
┌───────────────────────────── ECS (Ubuntu) ─────────────────────────────┐
│  Nginx  :80 / :8080                                                    │
│    ├── /                     → /var/www/job-copilot  (Vite 静态产物)   │
│    ├── /api/                 → 127.0.0.1:8000        (proxy_read 600s) │
│    ├── /conversation/image/  → 127.0.0.1:8000                          │
│    └── /api/v1/conversation/chat/stream → 同上，但 proxy_buffering off │
│                                                                        │
│  job-copilot.service (systemd, 用户 jobcopilot)                        │
│    └── uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1   │
│          └── backend/resources  ← 上传文件 / 解析文本 / FAISS 索引 / 导出 │
│                                                                        │
│  MySQL 8.0  :3306 (只监听 127.0.0.1)                                   │
│    └── llmrag 库（会话、消息、文档、简历版本、面试、JD 分析、知识条目）  │
└────────────────────────────────────────────────────────────────────────┘
                                   │ HTTPS
                                   ▼
                       阿里云百炼 DashScope（qwen-plus / qwen-vl-plus / text-embedding-v3）
```

### 约定（全文一致，脚本已按此实现）

| 项目 | 取值 |
|---|---|
| 代码目录 | `/opt/job-copilot`（`root:jobcopilot`，代码由 root 管理） |
| 运行态数据 | `/opt/job-copilot/backend/resources`（`jobcopilot:jobcopilot`，应用可写） |
| 配置文件 | `/opt/job-copilot/.env`（`root:jobcopilot` `640`） |
| Python 虚拟环境 | `/opt/job-copilot/backend/.venv`（release.sh 创建） |
| 前端静态产物 | `/var/www/job-copilot`（Nginx 读） |
| 备份 | `/var/backups/job-copilot`（`700`） |
| 后端监听 | `127.0.0.1:8000`（不直接暴露公网） |
| 站点端口 | **80 与 8080 同时监听**（裸 IP 访问 80 实测可用，8080 为备用入口） |
| 服务账号 | `jobcopilot`（system，无登录 shell） |

### 三条关键设计约束（别踩）

1. **`--workers 1`**：进程内持有 FAISS/BM25 检索缓存、BGE/LLM reranker 与惰性 LLM 单例。多 worker 会各持一份索引，且缓存语义从"进程内"变成"随机命中"。
2. **SSE 必须关缓冲**：`/api/v1/conversation/chat/stream` 若被 Nginx 缓冲，打字机效果会退化成"整段跳出"。`deploy/nginx-host.conf` 已用 `location =` 精确匹配 + `proxy_buffering off` 处理。
3. **数据写在本地盘**：`backend/resources` 与 MySQL 是全部状态。因此发布采用**原地更新 + 发布前自动备份**，不用 `releases/<时间戳>` + 软链（`config.py` 用 `Path.resolve()` 推导路径会穿透软链，切版本时数据目录会跟着变）。

### 端口策略（按实测结论修正）

规划时按"大陆未备案 → 只能 8080"来设计，实机探测后修正了结论：

| 端口 | 实测结果 | 结论 |
|---|---|---|
| 80 | 从公网可达（返回 nginx 的 502） | **可用**。受限的是"未备案域名"的解析与访问，裸 IP 走 80 是通的 |
| 443 | 连接被拒（有响应，说明安全组放行，只是没监听） | 备案后加证书即可用 |
| 8080 | 公网超时（丢包） | 安全组没放行；服务器本机 ufw/iptables 均未拦（已核实） |

因此最终做法是**同时监听 80 与 8080**：80 直接可用，8080 作为备用入口（在控制台补一条 TCP 8080 入方向规则后同样可用）。备案完成后再把 `server_name` 换成域名并加 443，见[附录 B](#附录-b备案完成后切-https)。

### 交付物（本次为部署而新增/修正的文件）

| 文件 | 作用 |
|---|---|
| `deploy/部署指南.md` | 本文档 |
| `deploy/.env.production.example` | 生产 `.env` 模板 |
| `deploy/bootstrap.sh` | 服务器一次性初始化（依赖、账号、目录、Nginx、systemd、Node、swap、时区） |
| `deploy/release.sh` | 服务器端发布（备份 → 同步 → 依赖 → 构建 → 重载 → 重启 → 健康检查） |

| `deploy/export-data.ps1` | **开发机**导出 MySQL + resources |

## 二、开发机准备

```powershell
# 1) 确认三件套可用（Windows 10 1809+ 自带 OpenSSH 与 tar）
ssh -V; scp -V; tar --version

# 2) 生成密钥并免密登录（比每次输密码省事，也便于脚本执行）
ssh-keygen -t ed25519 -C "job-copilot-deploy"
type $HOME\.ssh\id_ed25519.pub | ssh root@<公网IP> "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys"

# 3) 让发布脚本能免密 sudo（可选，省掉每次 ssh 输入 sudo 密码）
ssh root@<公网IP> "echo 'root ALL=(ALL) NOPASSWD:ALL' > /etc/sudoers.d/90-deploy && chmod 440 /etc/sudoers.d/90-deploy"
```

> 用 root 直连是最短路径；若你坚持用普通用户，把上面命令里的 `root` 换成你的用户名，并确保它在 `sudo` 组。

## 三、阿里云控制台配置

### 安全组入方向规则

| 协议 | 端口 | 授权对象 | 说明 |
|---|---|---|---|
| TCP | 22 | 你的出口 IP（`curl ifconfig.me` 查） | 不要对 `0.0.0.0/0` 开放 |
| TCP | 80 | `0.0.0.0/0` | 站点主入口（裸 IP 实测可用） |
| TCP | 8080 | `0.0.0.0/0` | 备用入口；不放行也不影响 80 可用 |
| ~~TCP~~ | ~~3306~~ | — | **绝不放行**。现状是它对开发机 IP 可达（旧原型留下的规则）；上线后请把这条规则删掉或至少收紧到你的出口 IP，应用在服务器上用 `127.0.0.1` 连库，不需要公网入口 |

出方向保持默认（全部放行）——服务器要访问 DashScope 的 HTTPS 接口。

### 其他

- **快照**：动手前给系统盘打一个快照，出问题可整体回滚。
- **备案**：域名备案是使用**域名**访问 80/443 的前置条件；备案期间用裸 IP 访问 80 是通的，不影响功能。
- **系统盘**：≥ 40GB。FAISS 索引与上传文件都在系统盘，磁盘满会导致索引写失败。
- **实例规格**：2C2G 可跑（`bootstrap.sh` 会补 2G swap）；4C8G 更从容。构建前端是内存峰值点。
- **先看端口有没有被旧服务占用**：这台机器上跑过旧原型（Flask），上线前确认 80 / 8080 / 8000 的占用情况，避免"配好了却访问到旧服务"：

```bash
sudo ss -lntp | grep -E ':(80|443|8000|8080|3306)\b'
systemctl list-units --type=service --state=running | grep -Ei 'flask|gunicorn|llmrag|nginx|mysql'
```

## 四、服务器初始化

### 4.1 上传代码（首次，手工一次即可）

```powershell
# 开发机：先只打包上传，不解包（-FirstTime 会在服务器上解包并初始化）
pwsh -File deploy\push.ps1 -Server root@<公网IP> -FirstTime
```

`-FirstTime` 在服务器上执行：

```bash
sudo mkdir -p /opt/job-copilot
sudo tar xzf /tmp/job-copilot-<时间戳>.tar.gz -C /opt/job-copilot
sudo bash /opt/job-copilot/deploy/bootstrap.sh          # 可加 --cn-mirror
```

### 4.2 `bootstrap.sh` 做了什么

| 步骤 | 内容 |
|---|---|
| 1 | 装 `nginx`、`mysql-client`、`rsync`、`apache2-utils`（htpasswd）、`libgomp1`（faiss 运行时需要）、Python 3.12（24.04 自带；22.04 走 deadsnakes，失败自动回退系统 `python3`） |
| 2 | 建系统账号 `jobcopilot` 与目录；内存 < 2G 时创建 2G swap；时区设为 `Asia/Shanghai` |
| 3 | 安装并启用 Nginx 站点（`deploy/nginx-host.conf` 同时监听 80 与 8080，`--web-port` 可改默认端口） |
| 4 | 安装 systemd 单元并 `enable` |
| 5 | 安装 Node.js 22（Vite 6 要求 ≥18，依赖树里的 `@vueuse` 要求 ≥22）；`--cn-mirror` 时把 pip/npm 换成国内源 |
| 6 | ufw 若启用则放行 22 与站点端口 |

常用参数：

```bash
sudo bash /opt/job-copilot/deploy/bootstrap.sh --cn-mirror          # 国内机器推荐
sudo bash /opt/job-copilot/deploy/bootstrap.sh --web-port 9090      # 换站点端口
sudo bash /opt/job-copilot/deploy/bootstrap.sh --no-node            # 不在服务器构建前端（须配 -Build 发布）
```

脚本幂等，可重复执行；此时服务还没法启动（缺 `.env` 与数据库授权）。

> 你这台是 **Ubuntu 24.04**，`python3.12` / `python3.12-venv` 系统自带，第 1 步不会走 deadsnakes PPA，通常一两分钟就装完系统依赖。

> 不想用脚本的话，等价的手工命令见[附录 D](#附录-d命令速查)。

## 五、MySQL 准备（库已在服务器上，不需要迁库）

已核实：这台 ECS 上的 MySQL 8.0.46 里，`llmrag` 库已经有本项目的全部 8 张表和真实数据。所以这一章不是"建库"，而是"让服务器上的应用能用上同一个库"。

### 5.1 先确认现状

```bash
mysql --version
sudo mysql -e "SELECT VERSION(), @@character_set_server, @@collation_server, @@time_zone, NOW();"
sudo ss -lntp | grep 3306            # 期望只听 127.0.0.1；若听 0.0.0.0 见第十一章
sudo mysql -e "SHOW TABLES FROM llmrag;"
```

期望看到 8 张表：`conversation_documents`、`conversation_messages`、`conversations`、`interview_messages`、`interview_sessions`、`job_analysis`、`knowledge_entries`、`resume_versions`。

### 5.2 让 `llmrag` 账号能从本机（127.0.0.1）登录

这个账号现有的授权主机是开发机的公网 IP（连接时服务端显示 `'llmrag'@'36.98.249.119'`）。**应用在服务器上用 `127.0.0.1` 连库时匹配的是 `'llmrag'@'localhost'` / `'llmrag'@'127.0.0.1'`**，没有对应授权就会报 `Access denied for user 'llmrag'@'localhost'`。用 root 补授权（口令沿用现有值）：

```bash
sudo mysql <<'SQL'
-- 复用现有账号与密码，只是把登录来源从"开发机 IP"扩到"本机"
CREATE USER IF NOT EXISTS 'llmrag'@'127.0.0.1' IDENTIFIED WITH mysql_native_password BY '现有密码';
ALTER  USER 'llmrag'@'127.0.0.1' IDENTIFIED WITH mysql_native_password BY '现有密码';
GRANT ALL PRIVILEGES ON llmrag.* TO 'llmrag'@'127.0.0.1';

CREATE USER IF NOT EXISTS 'llmrag'@'localhost' IDENTIFIED WITH mysql_native_password BY '现有密码';
ALTER  USER 'llmrag'@'localhost' IDENTIFIED WITH mysql_native_password BY '现有密码';
GRANT ALL PRIVILEGES ON llmrag.* TO 'llmrag'@'localhost';
FLUSH PRIVILEGES;
SQL

# 自测：两个来源都要能进
mysql -h 127.0.0.1 -u llmrag -p -e "SELECT COUNT(*) AS convs FROM llmrag.conversations;"
mysql -h localhost  -u llmrag -p -e "SELECT COUNT(*) AS convs FROM llmrag.conversations;"
```

要点：

- MySQL 8.0 用 `mysql_native_password` 可让 PyMySQL 走短认证路径；若报 `Plugin 'mysql_native_password' is not loaded`（8.4+/9.x 已移除），去掉 `WITH mysql_native_password` 即可——`release.sh` 会自动补装 `cryptography` 支持 `caching_sha2_password`。
- `GRANT ALL` 是必要的：`create_all` 要建表权限，`import-data.sh` 要建/删表权限（含备份时的读权限）。
- 账号口令以服务器上现有值为准，别照抄 `.env.example` 的占位符。

### 5.3 如果确实想用全新的库

只有想"干净重来"时才做。新库看不到历史会话，且第六章需要走 dump 导入路径：

```bash
sudo mysql <<'SQL'
CREATE DATABASE IF NOT EXISTS job_copilot
  DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER IF NOT EXISTS 'jobcopilot'@'127.0.0.1' IDENTIFIED WITH mysql_native_password BY '新密码';
GRANT ALL PRIVILEGES ON job_copilot.* TO 'jobcopilot'@'127.0.0.1';
FLUSH PRIVILEGES;
SQL
```

表结构不用手工建：`app/repositories/mysql_base.py` 在首次取会话时执行 `Base.metadata.create_all`。

### 5.4 写 `.env`

```bash
sudo cp /opt/job-copilot/deploy/.env.production.example /opt/job-copilot/.env
sudo vi /opt/job-copilot/.env      # 填 DASHSCOPE_API_KEY 与 MYSQL_PASSWORD
# MYSQL_HOST=127.0.0.1 / MYSQL_USER=llmrag / MYSQL_DATABASE=llmrag
sudo chown root:jobcopilot /opt/job-copilot/.env
sudo chmod 640 /opt/job-copilot/.env
```

`640 + root:jobcopilot` 是有意为之：systemd 以 root 读 `EnvironmentFile`，应用进程以 `jobcopilot` 读同名文件，两边都能读，其他用户读不到。

> ⚠️ 不要设 `RESOURCES_ROOT`——默认值就是 `/opt/job-copilot/backend/resources`，与脚本的权限/备份路径一致。

## 六、数据迁移：只搬 resources + 改写路径

库已经在服务器上，所以**数据本身不用搬**；要搬的是文件系统里的运行产物，要改的是库里记录的绝对路径。顺序不能颠倒。

### 6.1 开发机：先把旧原型产物归并进来

已核实的现状：3 份文档记录来自两个时代，其中 1 份（会话 `conv_20260928152722_8d0dd9`）的产物在旧原型目录 `F:\code\llmrag\resources` 下。先归并、再对账：

```powershell
pwsh -File deploy\merge-legacy-resources.ps1
# 本次已执行：新增 29 个文件；对账显示 3 份文档（6 个路径）全部能在本地 resources 找到
```

该脚本只归并 `uploads` / `parsed_docs` / `faiss_index_uploads` 三类按会话存放的产物；**不**归并 `faiss_index`、`faiss_index_knowledge`（索引必须与当前语料一致，部署后用 `POST /api/v1/knowledge/rebuild` 重建更干净），也不动旧原型的 `generated_docs`、`chat_history.json`。

> 对账若报"缺失"，说明那份文档的源文件确实找不到了：接受它检索失效、让用户重新上传，或把其他备份副本补进 `backend/resources`。

### 6.2 开发机：打包 resources（顺带留一份全库备份）

```powershell
pwsh -File deploy\export-data.ps1              # 库 + resources
pwsh -File deploy\export-data.ps1 -SkipDump    # 只打包 resources
```

产出在 `deploy\_artifacts\export-<时间戳>\`：

| 文件 | 用途 |
|---|---|
| `resources.tar.gz` | 要上传到服务器的运行产物 |
| `job_copilot.sql` | 全库 dump。库已在服务器上时它是**额外保险**而非迁移载体（改写路径出错时可回滚） |
| `export-manifest.txt` | 各表行数，用于与服务器对账 |

口令经 `MYSQL_PWD` 环境变量传给 `mysqldump`，不落命令行、不进日志。

```powershell
scp deploy\_artifacts\export-<时间戳>\resources.tar.gz root@<公网IP>:/tmp/
scp deploy\_artifacts\export-<时间戳>\job_copilot.sql  root@<公网IP>:/tmp/   # 想要离线备份时
```

### 6.3 服务器：铺开产物并改写路径

```bash
sudo bash /opt/job-copilot/deploy/import-data.sh --paths-only /tmp/resources.tar.gz
```

脚本做四件事：

1. 备份当前库到 `/var/backups/job-copilot/pre-import-<时间戳>.sql.gz`——**改写路径是在改数据，这一步是退路**；
2. 解包 `resources.tar.gz` 到 `/opt/job-copilot/backend/resources` 并校正属主；
3. 改写 `conversation_documents` 的 `stored_path` / `parsed_text_path`（见 6.4），并逐个检查文件是否存在；
4. 重启后端 + 健康检查，最后打印各表行数。

> 若确实要把库搬到服务器或换库名，去掉 `--paths-only` 并给出 dump：`import-data.sh /tmp/job_copilot.sql /tmp/resources.tar.gz`。

### 6.4 为什么必须改写路径

`conversation_documents` 存的是**上传时的绝对路径**，且来自两个时代：

```text
f:\code\llmrag\resources\uploads\conv_20260928152722_8d0dd9\...pdf                 ← 旧原型
F:\code\job-copilot\backend\resources\uploads\conv_20260615141948_14f7c5\...pdf    ← 当前项目
```

不改写有两级后果：

1. 明显症状：旧会话的文档检索、简历评分、面试、JD 分析读不到解析文本，功能像"坏了"；
2. **隐蔽症状**：在旧会话里再传一份新文档会触发 `rebuild_conversation_index`，路径不存在的旧文档被跳过 → 旧文档从 FAISS 索引里静默消失，且不报任何错。

`fix_resource_paths.py` 取路径中最后一个 `resources/` 之后的部分重建成服务器路径，**兼容上面两种前缀**、幂等、可反复执行。核对：

```bash
mysql -h 127.0.0.1 -u llmrag -p llmrag -e \
  "SELECT document_id, stored_path, parsed_text_path FROM conversation_documents\G"
```

期望三条记录的 `stored_path` / `parsed_text_path` 都以 `/opt/job-copilot/backend/resources/` 开头。

> ⚠️ **共用一个库的代价**：改写后开发机上的本地应用就找不到这几个文件了（路径已指向 Linux）。想在本机继续开发，建议本地另起一个 MySQL（把 `job_copilot.sql` 或 `/var/backups/job-copilot/pre-import-*.sql.gz` 导进去）；临时反向改写也可以：
> `python deploy\fix_resource_paths.py --resources-root F:\code\job-copilot\backend\resources`

### 6.5 迁移验收

## 八、Nginx 与访问

`bootstrap.sh` 已装好站点，这里说明要点与可选加固。

> **`server_name` 是模板占位符**：仓库里的 `deploy/nginx-host.conf` 写的是 `server_name __SERVER_NAME__;`（避免把真实公网 IP 带进公开仓库）。`bootstrap.sh` 安装时会自动替换成本机公网 IP，或你传入的域名 `--domain your.domain.com`。手工安装时必须自己替换，否则请求匹配不到这个 server 块（会落到 nginx 默认站点）：
>
> ```bash
> sudo sed "s/__SERVER_NAME__/<公网IP或域名>/" deploy/nginx-host.conf \
>   | sudo tee /etc/nginx/sites-available/job-copilot >/dev/null
> ```

| 配置 | 值 | 漏了会怎样 |
|---|---|---|
| `location = /api/v1/conversation/chat/stream` + `proxy_buffering off` | 关闭缓冲 | 打字机效果变成整段跳出 |
| `proxy_read_timeout 600s` | 比前端 axios 的 300s 更长 | 长回答会在中途 504 |
| `client_max_body_size 25m` | 上传上限 20MB + 余量 | 上传 413 |
| `root /var/www/job-copilot` + `try_files $uri $uri/ /index.html` | SPA 回退 | 刷新子路由 404 |
| `location /conversation/image/` | 图片反代 | 历史消息里的图片 404 |
| `gzip off`（SSE 段内） | 避免 gzip 缓冲 | 流式被攒块 |

### 强烈建议：开启 Basic Auth

**应用本身没有登录态**，只要站点对公网开放，任何人都能调用并消耗你的 DashScope 额度。用脚本一步搞定：

```bash
sudo bash /opt/job-copilot/deploy/enable-basic-auth.sh                 # 自动生成 20 位强密码并启用
sudo bash /opt/job-copilot/deploy/enable-basic-auth.sh -p '新密码'      # 轮换密码
sudo bash /opt/job-copilot/deploy/enable-basic-auth.sh -u 自定义用户名 -p '密码'
sudo bash /opt/job-copilot/deploy/enable-basic-auth.sh --disable       # 关闭门禁（排查问题时用）
```

脚本做的事：用 `htpasswd -iB`（bcrypt；口令经标准输入传递，不出现在 `ps` 里）写 `/etc/nginx/.htpasswd`（`640 root:www-data`）→ 在站点配置里启用 `auth_basic`（幂等）→ `nginx -t` + reload → 轮询等 401 稳定出现后**逐个端口**验证"未认证=401 / 已认证=200"，并打印凭据。

验证（公网）：

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://<公网IP>/                     # 401
curl -s -u jobcopilot:'密码' http://<公网IP>/api/v1/system/health            # success
```

使用时要知道的四点：

1. 浏览器首次打开会弹**原生登录框**；认证一次后页面内所有请求（含 SSE 的 `fetch`）自动带凭据，无需额外配置。
2. **Basic Auth 没有"退出登录"**：换账号要关浏览器或开无痕窗口。
3. 静态资源 `/assets/*` 与 API 同属一个 `auth_basic` 作用域，都受保护。
4. ⚠️ **HTTP 下 Basic 凭据只是 base64，不是加密**：能挡住扫描器与陌生人，挡不住链路嗅探。备案 + HTTPS（[附录 B](#附录-b备案完成后切-https)）之后才真正安全。

> 📌 **仓库配置与线上配置的差异（有意为之）**：`deploy/nginx-host.conf` 里的 `auth_basic` 两行**保持注释**——否则全新机器跑 `bootstrap.sh` 时会因为还没有 `/etc/nginx/.htpasswd` 导致 `nginx -t` 失败。启用/关闭一律走 `enable-basic-auth.sh`（它改的是服务器上的 `/etc/nginx/sites-available/job-copilot`）。`release.sh` 不会覆盖站点配置，所以发布不会把门禁弄丢；只有重新跑 `bootstrap.sh` 才会覆盖，届时再执行一次 `enable-basic-auth.sh` 即可。

其它加固见[第十一章](#十一安全加固清单)。

## 十一、安全加固清单

按性价比排序，前两项建议当天做完。

1. **给站点加门禁**（Basic Auth 见第八章，或安全组里把 8080 的来源限定为你自己的 IP）。这是最重要的一条：应用没有账号体系。
2. **`.env` 权限**：`root:jobcopilot 640`，并且确认 `.env` 不在任何 Git 仓库里（`.gitignore` 已含）。
3. **收紧 CORS**：`backend/app/main.py` 现在是 `allow_origins=["*"]`。同源部署（前端与 API 同域）后可以改成你的站点地址：
   ```python
   allow_origins=["http://<公网IP>:8080"],
   ```
   改完走一次正常发布即生效。
4. **关闭或保护 `/docs`**：它会把全部接口暴露成可交互文档。若不需要：
   ```nginx
   location /docs { deny all; }
   location /openapi.json { deny all; }
   ```
   在需要时可以用 Basic Auth 单独保护而不是全禁。
5. **限流**：LLM 接口最贵，可在 `http {}` 段加：
   ```nginx
   limit_req_zone $binary_remote_addr zone=chat:10m rate=10r/m;
   # 然后在 SSE 与 /api/ location 里：
   # limit_req zone=chat burst=5 nodelay;
   ```
6. **MySQL 不对外**：`bind-address = 127.0.0.1`，安全组不放 3306。
7. **防火墙**：ufw 只放 22 与站点端口；22 的来源尽量限制。
8. **fail2ban**（可选）：防 SSH 爆破。
9. **密钥轮换**：DashScope Key 只存在服务器 `.env` 里；若曾出现在聊天记录/截图里，去百炼控制台重置。
10. **系统更新**：`sudo apt update && sudo apt upgrade -y`，尤其是 `nginx` 与 `openssl`。

## 十二、故障排查

先看日志，再对症：

```bash
sudo journalctl -u job-copilot -n 100 --no-pager
sudo tail -n 100 /var/log/nginx/job-copilot.error.log
```

| 现象 | 原因 | 处理 |
|---|---|---|
| 浏览器打不开站点 | 安全组没放行 / ufw 拦 / Nginx 没起 / 访问的是没放行的端口 | 三层依次查：控制台安全组 → `sudo ufw status` → `systemctl status nginx`；8080 未放行时先用 80 |
| 502 Bad Gateway | 后端没起或端口不对 | `systemctl status job-copilot`；`ss -lntp \| grep 8000` |
| 504（长回答） | Nginx 读超时太短 | `proxy_read_timeout 600s`（本方案已配） |
| 打字机变整段下发 | SSE 路径被缓冲 | 确认走的是 `location = /api/v1/conversation/chat/stream`，且 `proxy_buffering off` |
| 上传报 413 | 体积限制 | `client_max_body_size 25m`（本方案已配）；同时确认文件 < 20MB |
| 上传成功但检索不到内容 | 迁移遗留：`parsed_text_path` 还是旧绝对路径 | 跑 `import-data.sh --paths-only` 或 `fix_resource_paths.py`；日志里没有报错但检索为空就是这个 |
| 旧会话里的文档"消失" | 同上，且已被 `rebuild_conversation_index` 剔除 | 修好路径后在会话里重新上传一次该文档即可重建索引 |
| 首次对话很慢 | 嵌入模型/索引首次懒加载 | 正常现象；预热一次即可 |
| 启动即崩，日志含 `cryptography is required` | MySQL 8 `caching_sha2_password` 全量认证 | `/opt/job-copilot/backend/.venv/bin/pip install cryptography`（release.sh 已自动处理） |
| 启动即崩，`Access denied for user 'llmrag'@'localhost'` | 授权主机只开了开发机 IP，没有本机来源 | 按 5.2 补 `'llmrag'@'127.0.0.1'` 与 `'llmrag'@'localhost'` 并 `GRANT` |
| 部署后看不到历史会话 | `.env` 指向了新建的空库 | 把 `MYSQL_DATABASE` 改回 `llmrag` 后重启；或在空库里走 dump 导入 |
| 旧会话的文档路径指向 Linux，开发机本地跑不通了 | 两个环境共用一个库，路径只能是一份 | 本地另起 MySQL 导入 dump（6.4 的说明） |
| `Unknown collation: utf8mb4_0900_ai_ci` | 8.0 的 dump 导入 5.7 | 用 `import-data.sh`（会自动降级排序规则） |
| `npm run build` 被杀（Killed） | 内存不足 | 确认 swap 已生效 `swapon --show`；或开发机 `-Build` 后带 `--skip-frontend` |
| `pip install` 中途 OOM | 同上 | 加 swap；或 `--no-cache-dir`（脚本已带） |
| 时间显示差 8 小时 | 服务器时区不对 | `sudo timedatectl set-timezone Asia/Shanghai && sudo systemctl restart job-copilot`（历史数据时间不会自动修正） |
| 刷新子路由 404 | SPA 回退缺失 | Nginx 里保留 `try_files $uri $uri/ /index.html` |
| 页面白屏但接口正常 | 前端产物没发布 | `ls /var/www/job-copilot/index.html`；重跑 `release.sh` |
| 磁盘满 | 上传文件与备份堆积 | `df -h`；清理旧备份/旧上传；考虑备份异地化 |
| 定时备份没生成文件，`/var/log/job-copilot-backup.log` 里是 `Permission denied` | Windows 上传的 `.sh` 没有执行位（644），而 cron 是直接执行脚本 | 把 cron 命令改成 `bash /opt/job-copilot/deploy/backup.sh`，并 `chmod 755 /opt/job-copilot/deploy/*.sh`（`release.sh`/`bootstrap.sh` 现在会自动补执行位） |
| 停用了 `sites-enabled` 里的站点但旧站点仍生效（`conflicting server name`） | nginx 的 `include /etc/nginx/sites-enabled/*;` 中 `*` **也匹配 `xxx.disabled`** | 把停用的站点**移出该目录**（配置本体留在 `sites-available/`，需要时重建软链即可恢复） |
| 某端口公网不通、本机 curl 却正常 | "超时"= 安全组丢包；"连接被拒"= 安全组已放行但没人监听 | 超时查安全组规则；拒连查 `ss -lntp` |
| 脚本中途莫名停止，后面步骤没执行 | `set -e` 遇到探针命令的非零退出码（`crontab -l`、`systemctl is-active`、`grep` 无匹配） | 这类命令加 `\|\| true`；本次部署在装 cron、查服务状态时各踩过一次 |
| 刚启用 Basic Auth 时"未认证也能打开" | nginx 是优雅重载，旧 worker 短时间内仍接新连接 | 等 1–2 秒再测；`enable-basic-auth.sh` 已内置轮询等待 |
| 忘了门禁密码 / 想换用户名 | — | `sudo bash /opt/job-copilot/deploy/enable-basic-auth.sh -u 用户名 -p '新密码'` |
| 命令行 curl 全部 401 | 站点已开门禁 | 加 `-u 用户名:密码`；如需临时关闭：`enable-basic-auth.sh --disable` |
