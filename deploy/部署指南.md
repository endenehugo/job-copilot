# 部署指南（阿里云 Ubuntu · 非 Docker 路线）

> 对应环境：Ubuntu 22.04 / 阿里云 ECS，安全组放行 22 与 80。Docker 路线见 `docker-compose.yml`，二者选其一。

## 一、准备

```bash
# 系统依赖
sudo apt update && sudo apt install -y python3.12-venv nginx

# 代码
sudo mkdir -p /opt/job-copilot && sudo chown $USER /opt/job-copilot
# git clone 或 rsync 上传仓库（backend/ 与 deploy/ 必需）

# 数据库（管理员执行；表结构由后端首次连接时自动创建）
mysql -u root -p -e "
CREATE DATABASE IF NOT EXISTS job_copilot DEFAULT CHARACTER SET utf8mb4;
CREATE USER IF NOT EXISTS 'jobcopilot'@'%' IDENTIFIED BY '<强密码>';
GRANT ALL PRIVILEGES ON job_copilot.* TO 'jobcopilot'@'%';
FLUSH PRIVILEGES;"
```

## 二、后端

```bash
cd /opt/job-copilot/backend
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

`/opt/job-copilot/.env`（600 权限，不入库）：

```ini
APP_ENV=prod
DASHSCOPE_API_KEY=sk-xxxx
METASO_API_KEY=mk-xxxx
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_USER=jobcopilot
MYSQL_PASSWORD=<强密码>
MYSQL_DATABASE=job_copilot
```

> ⚠️ 生产环境不要安装 torch：torch 自带的 OpenMP 运行库与 faiss-cpu 冲突。
> 生产依赖已在 `requirements.txt` 中最小化，不需要 `KMP_DUPLICATE_LIB_OK`。

systemd 单元 `/etc/systemd/system/job-copilot.service`：

```ini
[Unit]
Description=Job Copilot backend
After=network.target mysql.service

[Service]
User=www-data
WorkingDirectory=/opt/job-copilot/backend
EnvironmentFile=/opt/job-copilot/.env
ExecStart=/opt/job-copilot/backend/.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

```bash
sudo chown -R www-data /opt/job-copilot
sudo systemctl daemon-reload
sudo systemctl enable --now job-copilot
curl http://127.0.0.1:8000/api/v1/system/health   # 验证
```

> **为什么 workers=1**：进程内持有 FAISS/BM25 缓存、BGE reranker 与惰性 LLM 单例；
> 多 worker 会重复加载索引并各自为政。扩容前置条件：会话历史已在 MySQL（已满足），
> 但进程内检索缓存需迁移 Redis 或接受每 worker 一份内存副本。

## 三、前端

```bash
cd /opt/job-copilot/frontend
npm ci
npm run build          # 产物 dist/
sudo mkdir -p /var/www/job-copilot
sudo cp -r dist/* /var/www/job-copilot/
```

Nginx 站点 `/etc/nginx/sites-available/job-copilot`（与 `deploy/nginx.conf` 一致，
把 `proxy_pass http://backend:8000` 保持不变）：

```bash
sudo ln -s /etc/nginx/sites-available/job-copilot /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

要点（已写在 deploy/nginx.conf）：

- `/api/v1/conversation/chat/stream` 必须 `proxy_buffering off`，否则 SSE 打字机效果失效；
- 常规 `/api/` 与 `/conversation/image/` 反代到 127.0.0.1:8000，读超时 300s（LLM 长请求）；
- `client_max_body_size 25m`（上传上限 20MB + 余量）；
- SPA 回退 `try_files $uri /index.html`。

## 四、验收

1. `curl http://<服务器IP>/api/v1/system/health` 返回 success 信封；
2. 浏览器打开 `http://<服务器IP>/`，走一遍演示脚本：
   新建会话 → 上传简历 → JD 分析（雷达图）→ 项目优化 → 模拟面试 → 导出；
3. 聊天观察打字机效果（流式生效的标志是逐字出现而不是整段跳出）；
4. `sudo journalctl -u job-copilot -f` 看后端日志。

## 五、常见问题

| 现象 | 原因与处理 |
|---|---|
| 流式回答整段跳出 | Nginx 未对该路径关 buffering，或中间层缓存 |
| 502 | 后端未起/端口不对，`systemctl status job-copilot` |
| 上传 413 | `client_max_body_size` 未配置 |
| 首次对话很慢 | 嵌入模型与 reranker 懒加载在首次请求时初始化，属正常 |
| MySQL 连接失败 | 检查 .env 与账号授权（GRANT 到库级） |
