# 默认单栏高密度技术简历：版式与内容规则

本文件是 `/make-resume` 深入规则。**完整可复制的 HTML 骨架写在 SKILL.md 末尾**，本文件只讲参数、取舍和禁止事项。

## 适用场景

默认风格是 ASu 同款单栏高密度中文技术简历，适合应届生、实习生和 AI/Agent/LLM/后端工程方向候选人。强调"身份定位 → 公开背书 → 项目全景 → 个人职责 → 技术证据"，不把经历写成无法追问的宣传文案。

## 页面结构

1. **顶部信息区**：姓名、电话、邮箱、微信/主页、身份、目标岗位、GitHub/开源身份、学校和毕业时间；最右侧预留证件照位置。
2. **经历分区**：蓝色粗体标题 + 细蓝线分隔，默认顺序"实习经历 → 项目经历 → 校园经历 → 技能与其他"；内容不足时不强行分页留白。
3. **公司条**：浅灰圆角背景，左侧公司/平台名，中间团队/业务/岗位，右侧时间与公开链接。
4. **项目标题**：蓝色加粗，附带起止时间与身份标签。
5. **项目要点**：按"背景/目标 → 我的职责 → 关键技术动作 → 结果证据"排列；每个项目 2—5 条，技术细节用缩进子弹点展开。
6. **分页**：内容能在正常字号下形成完整信息闭环时优先单页；双页时第一面放最强实习/核心项目并先填实，第二面承接补充项目、开源、论文、技能和奖项。长项目在自然段落处分页，不截断标题和子弹点。

## 视觉参数

- 纸张：A4，`@page { size: A4; margin: 12mm; }`；屏幕预览用 `.sheet { width: 186mm; }` 近似，打印时还原为 `width: auto`。
- 正文：9.5—10.5 pt，行距 1.25—1.42。
- 姓名：20—24 pt，黑色加粗；顶部定位和联系信息紧凑排列。
- 分区标题：13 pt，蓝色 `#2458B8`，下方 1.5 px 蓝线。
- 项目标题：11—13 pt，蓝色加粗；正文黑色，关键词可加粗但不要整段加粗。
- 公司条：背景 `#F3F4F6`，圆角 6 px；`.bar-time` 用 `margin-left: auto` 右对齐。
- 链接：蓝色，可见文字保留规范化 URL、DOI 或可识别的"域名/关键路径"；打印后不能只剩"网站""PAPER""CODE"等标签。长地址去掉无关追踪参数后允许换行。
- 字体：中文统一优先 `Microsoft YaHei`、`PingFang SC`、`Source Han Sans SC`、`SimHei` 等黑体；英文使用同类无衬线并留通用回退。
- 证件照：右上角框 26×36 mm，`object-fit: cover` 防拉伸；占位框只在还没有照片时保留。
- `.item` 必须带 `page-break-inside: avoid`，避免单个经历被拆到两页。

## 资源约束（本平台）

- **不要引用任何本地图标/Logo 目录**，本平台不存在 `assets/icons/`、`assets/logos/`、`assets/templates-html/`。
- 联系方式的分隔用纯文本 `·` 或空格，不要用 Emoji，也不要引用不存在的 SVG。
- 公司/平台的品牌 Logo 只有在用户自己提供了可用 SVG URL 时才放；否则一律用纯文字公司条，不用相似 Logo 代替。
- 简历必须**自包含**：除用户自备的照片 URL 外不得引用任何外部 CSS/JS/图片，保证断网也能打开。

## 内容规则

- 保留正式职位、公司、时间和教育背景，不用模板制造更高职级。
- 每个"Owner、主导、架构、0→1、核心作者"都要能由职责、提交、上线或评审证据支撑。
- 项目总调用量、用户数、Star/Fork 等指标要标明口径；项目数据不能自动算成个人数据。
- 先写个人贡献，再写技术栈；技术名词后面必须有动作或结果。
- 不确定的信息用 `【待补：指标/职责/链接】` 标记，交付说明里集中让用户核对。
- 占位文本统一包一层 `<span class="pending">`（橙褐色），方便用户全局搜索替换。

## 输出与校验

产物永远是可编辑 HTML，不是整页截图。生成后对照 SKILL.md 的"交付前 QA 自查清单"逐条过一遍再交付。
