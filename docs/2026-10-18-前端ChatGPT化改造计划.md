# 前端 ChatGPT 化改造计划

> 目标：把现有「控制台式」界面改成截图里的 ChatGPT 式对话界面——扁平侧栏 + 居中内容列 + 底部大圆角输入卡 + 无头像的纯文本回答。
> 约束：只动视图层（`.vue` 模板与 CSS），不改 store 数据契约、不改后端接口、不改 SSE 协议。

## 一、先说结论

1. **不引入 AI 组件库**。理由见第五节，核心是：我们的聊天组件一共 250 行，而两个候选库的默认视觉都是 Ant/Element 味，改到 ChatGPT 外观的成本不比手写低，还要承担第二套设计系统与 peer 依赖。
2. **保留 Element Plus，但降级为「表单控件供应商」**。`el-dialog / el-select / el-progress / el-tag` 继续用；`el-collapse`、`el-input(textarea)` 在壳层退场，因为它们的默认外观正是「后台管理」感的来源。
3. **改造重点不是换色，是三件事**：侧栏信息架构扁平化、空态/对话态共用同一个输入卡、回答区去掉头像与边框。只换配色不会产生截图里的观感差异。
4. **截图里有、但本项目没有的能力不做假按钮**（图像生成、定时任务、语音输入、深度研究、项目空间）。照着抄会做出点不动的空壳，面试演示时是负分。

## 五、技术选型：为什么不用现成 AI 组件库

| 候选 | 能力 | 判断 |
|---|---|---|
| `vue-element-plus-x`（Element 生态，Bubble / Sender / Welcome / Thinking） | 与现有 EP 同源，无需第二套设计系统 | **不采用**：其 Sender/Bubble 默认即"气泡+边框"外观，我们要的正是去掉这些；`useXChat / useXStream` 会与我们已有的 `stores/chat.js`（SSE 解析、停止生成、`tool_status`）重复，替换等于重写数据层 |
| `ant-design-x-vue`（Bubble / Sender / Conversations / ThoughtChain，peer 依赖 ant-design-vue） | 组件最全、最接近"AI 界面" | **不采用**：会同时打入 ant-design-vue 与 element-plus 两套组件库，构建体积与样式冲突成本高；我们的消息结构自定义字段多（sources / verification / files / warnings / toolStatus），套它的 Message 类型反而要写适配层 |
| Tailwind + shadcn-vue | 样式层最灵活，最接近"从零搭" | **不采用**：与 EP 并存等于两套设计系统；`el-dialog / el-select` 的样式仍要覆盖，收益只在纯新建项目成立 |
| 手写壳层 + 复用 EP 控件 | 无新依赖，改的是 5 个文件 + 3 个新文件 | **采用**。参考上述两库的交互细节（Sender 的 `+` 菜单结构、BubbleList 的自动滚动策略），只借设计不引依赖 |

判断依据：这次要改的是"外观与信息架构"，不是"聊天组件能力"。现有组件已经在处理流式增量、节流渲染（`MessageItem.vue:26-59`）、上翻时不打扰的自动滚动（`MessageList.vue:26-40`）——这些是花过调试成本的东西，换库等于丢掉。

### P3 输入卡统一（本次改造的核心）
- `Composer.vue` 支持 `variant: hero | docked`：同一组件实例，只切换外层 grid 位置，**不要用 `v-if` 在两个位置渲染两份**——否则首条消息发出时组件重挂载，输入内容、焦点、上传中的图片状态全丢。
- 新增 `components/chat/PlusMenu.vue`：点击 `+` 展开分组菜单（行 = 图标 + 标题 + 说明），Esc / 点击外部关闭。
- 空态与对话态共用：空态居中（`margin: auto`），有消息后贴底（`margin-top: auto`）。
- 删掉空态里的 chip 墙与虚线任务卡；能力全部收进 `+` 菜单。

### P4 消息层
- `MessageItem.vue`：去头像；assistant 纯文本（内容列 768px、`white-space` 正常折行）；user 浅灰气泡右对齐（`max-width 70%`、圆角 20）。
- 回答下方新增 hover 操作条：复制（已有 `utils/clipboard.js`）。**不做"重新生成"**——后端没有对应接口，做了就是假按钮。
- `tool_status` 改为一行可折叠的"思考中 / 已执行 N 步"，弱化视觉权重（当前是虚线框，抢注意力）。
- `SourcePanel` / `FileCards` 改为紧凑卡片 + 分隔线，去边框套边框。
- 保留 `warnings` 与降级提示的显式展示（`MessageItem.vue:74-76`）——项目有过"静默失败"整改历史，样式改版不能把它们藏在折叠里。

### P5 子视图对齐

## 七、回归清单（改样式最容易打断的行为）

1. 新建对话 → 发首条消息自动建会话，标题/预览刷新
2. 流式逐字渲染、`streaming` 光标、停止生成保留已生成部分
3. 切会话时旧流被中断且不回填到新会话（`selectSeq` 机制）
4. 图片上传：多选、10MB/空文件拦截、缩略图删除、随消息发送
5. 文档上传 → `pending` 轮询 → `indexed` / `failed`
6. 简历版本切换与四维评分展示
7. 知识库：重建索引 / 提交 AI 审核 / 自主扩充
8. 会话树：展开懒加载、右键删除、`localStorage` 记住展开态、子记录三种类型打开
9. 三个子视图：打开 / 返回会话 / 导出
10. 来源面板展开 + 风险徽章四态（low / medium / high / unknown 颜色不可混）
11. 降级 `warnings` 提示仍可见
12. `<900px`：侧栏可打开（当前是直接消失）
13. 上翻阅读时流式输出不抢滚动位置；`回到底部` 按钮出现

## 八、范围边界（明确不做）

- 深色模式（截图是浅色；做暗色要把 26 处 EP 变量 + 语义色全部成对定义，属于另一个任务）
- 语音输入、图像生成、定时任务、深度研究、项目空间（后端无对应能力）
- 顶部中间的「聊天 / 工作」分段（`chat` 目前只有 `mode: 'agent'` 一种，做分段是空壳）
- 消息编辑 / 重新生成（无接口）
- 移动端深度适配（先保证 900px 以上可用 + 侧栏抽屉）

## 九、需要你定的四件事

1. **视觉取向**：严格复刻（黑白灰 + 黑主按钮，蓝色只留语义）／ 借形保留品牌蓝？
   → 我倾向严格复刻，但提醒一点：像素级复刻在面试演示里容易被读成"照抄"。折中方案是布局与密度严格对齐，品牌标识与主按钮保留一点差异。
2. **范围**：只做聊天壳（P1-P4，约 8 个文件）／ 连三个子视图一起（P5）？
   → 建议先壳后视图，壳层完成即可截图交付。
3. **侧栏里的子记录**（面试/JD 分析/项目优化）保留嵌套树，还是挪到右侧抽屉按会话展示？
   → 嵌套树信息密度高但离 ChatGPT 的"单层最近列表"最远，这是本项目最特殊的一处；我倾向保留（功能价值 > 像素一致），只把它做轻。
4. **侧栏底部身份区**显示什么：真实模型名（接 `modelsApi`）／ 管理员登录入口（`authApi` 已存在未接入）／ 静态文案？
