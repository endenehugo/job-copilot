# 模型路由与免费额度降级机制

日期：2026-10-12
状态：已实现（一期静态路由 + 额度错误自动降级）

## 背景

百炼（DashScope）新用户免费额度按**模型独立**发放：每个模型约 100 万
token、90 天有效，模型之间不互通；某模型额度耗尽后**服务端不会自动
切换**，官方 FAQ 明确要求手动改 `model` 参数。另外，百炼没有公开 API
可用 DashScope Key 查询剩余免费额度（只能在控制台查看），因此"自动
获取额度"不可行，本方案用"错误驱动降级 + 配置声明"替代。

## 实现

### 1. 配置项（backend/app/core/config.py）

| 配置 | 默认值 | 说明 |
|------|--------|------|

| `llm_compatible_base_url` | 百炼兼容模式端点 | 默认 `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| `llm_fixed_temperature_models` | `{"kimi-k3": 1.0}` | 只接受固定温度的模型 |
| `llm_models_without_top_p` | `["kimi-k3"]` | 不支持 `top_p` 的模型 |
| `llm_fallback_models` | `["qwen3.8-flash", "qwen-flash", "deepseek-v4.1-flash", "qwen-plus", "qwen3.8-2.4t-a95b", "kimi-k3"]` | 额度类错误时的降级链（便宜 → 贵） |

### 1.1 端点差异：为什么新模型会报 `url error`（2026-10-12 实测）

langchain_community 0.3.25 的 `chat_models/tongyi.py` 在 `validate_environment`
里用一份**内置白名单**决定走哪个 DashScope 原生端点：模型名命中
`["qwen-audio-turbo", "qwen-vl-plus", "qwen-vl-max", ...]` 或名字里含 `"vl"`
才用 `dashscope.MultiModalConversation`（multimodal-generation 端点），
其余一律用 `dashscope.Generation`（text-generation 端点）。

百炼侧的实际划分是：`qwen-plus` / `qwen-flash` / `qwen-max` / `qwen-turbo` 等
老模型在 **text-generation** 端点，而 3.x / 3.8 这一代模型与第三方模型
（`deepseek-*` / `kimi-*`）都在 **multimodal-generation** 端点。白名单落后于
新模型，于是它们被发到了错的端点，服务端返回：

```
400 InvalidParameter: url error, please check url
```

实测矩阵（真实 Key，`build_chat_llm(...).invoke("只回复 OK")`）：

| 模型 | ChatTongyi 原生 | `/compatible-mode/v1` | 原生 multimodal 端点 |
|------|-----------------|------------------------|----------------------|
| `qwen-turbo` / `qwen-flash` / `qwen-plus` / `qwen-max` | ✅ | ✅ | ❌ url error |
| `qwen3.5-flash` / `qwen3.7-plus` / `qwen3.8-*` / `deepseek-v4.1-flash` / `kimi-k3` | ❌ url error | ✅ | ✅（但流式在 langchain 里抛 `sequence item 0: expected str instance, list found`，`content` 也变成 `[{'text': ...}]` 列表） |

结论：**这 5 个新模型统一走百炼 OpenAI 兼容模式**；原生 multimodal 端点虽能通，
但 content 结构与流式都与现链路不兼容。

### 1.2 双客户端实现（backend/app/core/llm_factory.py）

降级链逻辑抽到与客户端无关的 `QuotaFallbackMixin`（`_model_chain` /
`_switch_to` / `_generate` / `_stream`），两个具体类共用：

| 类 | 基类 | 用于 |
|----|------|------|
| `FallbackChatModel` | `ChatTongyi`（原生端点） | 老模型，保持现网行为不变 |
| `CompatibleFallbackChatModel` | `ChatOpenAI`（兼容模式端点） | `llm_compatible_mode_models` 里的新模型 |

`build_chat_llm` 按主模型自动选客户端，并处理两个坑：

1. **原生链剔除新模型**：主模型走原生端点时，把链上这一代新模型剔掉——它们在
   原生端点只会 400，而 `url error` 不在额度错误标记里，不会继续降级，等于把请求打死。
   兼容模式对老模型同样可用，所以反方向（兼容链里放老模型）没有问题。
2. **第三方模型采样参数**：`kimi-k3` 只接受 `temperature=1`，且完全不支持 `top_p`
   （传 0.7 直接 `400 InvalidParameter`）。工厂在构造时与**每次降级切换时**都按
   `llm_fixed_temperature_models` / `llm_models_without_top_p` 修正参数
   （`CompatibleFallbackChatModel` 另存 `base_temperature`，切回普通模型时还原）。

顺带记录的既有事实：`ChatTongyi` 没有 `temperature` 字段（pydantic 忽略未知入参），
所以**原生链路里调用方传的 temperature 一直是空转**，只有兼容模式链路真正生效。


### 2. 降级链（backend/app/core/llm_factory.py）

`QuotaFallbackMixin` + 两个具体客户端（见 1.2）：

- **触发条件**：异常文本命中额度/权限类标记
  （`AllocationQuota` / `FreeTierOnly` / `Arrearage` / `QuotaExhausted` /
  `InvalidApiKey` / `AccessDenied` / `Model.NotFound` / `Model.NotExist`）。
  限流（Throttling）不降级——已有 `max_retries` 兜底，避免瞬时抖动导致
  粘性降级。
- **切换方式**：改写 `model_name`（两个基类的 `_default_params` 都读它），
  对 `bind_tools` 绑定的调用同样生效；切换时同时按模型修正采样参数。
- **粘性生效**：切换在进程内持久，额度耗尽不会自愈，粘住降级模型是
  预期行为；lru_cache 单例因此天然记住降级状态。
- **流式安全**：DashScope 错误在流的首个分片前抛出，`_stream` 缓冲
  首个分片实现"零输出阶段"安全降级；一旦已产出内容则原样抛出
  （客户端已收到部分输出，无法回滚）。
- **正常路径零开销**：不命中降级条件时与基类客户端等价。

### 3. 调用点分流

| 服务 | 模型 |
|------|------|
| context_compression（会话历史压缩） | `llm_small_model` |
| context_verification（事实校验） | `llm_small_model` |
| document_index（listwise 重排 + per_doc 打分） | `llm_small_model` |
| conversation_chat（问答主链路，含工具绑定） | `llm_model` |
| resume_scoring / project_rewrite / interview / job_description / knowledge_review | `llm_model` |
| image_analysis / 会话多模态 | `multimodal_model` |

## 使用建议

- **最大化白嫖免费额度**：`.env` 里把 `LLM_MODEL` 设为清单里最便宜的
  `qwen3.8-flash`（0.8/2.7），主链路也走小模型（牺牲部分回答质量）；
  默认配置下主链路是 `qwen3.8-max`，后台结构化任务走 `qwen3.8-flash`。
- **换模型**：改 `LLM_MODEL` 为「可更换的模型清单」里任意一个即可，无需改代码；
  新旧两代模型混用也没问题（工厂按模型自动切换客户端）。
- **避免意外扣费**：建议在百炼控制台开启"免费额度用完即停"，
  配合本降级链，额度耗尽时会自动切到链上下一个有额度的模型。
- 额度可在控制台"额度管理"页查看；`tools/qwen_free_models/` 里的小工具可以
  用同一个 Key 列出账号可免费用模型并**实测**额度是否还能用（`list --verify`）。
