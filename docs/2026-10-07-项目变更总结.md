# 项目变更总结：从 llmrag 原型到 job-copilot

> 日期：2026-10-07。范围：job-copilot 仓库全部 17 个提交（重构启动 → 五阶段交付 → 上线后迭代）。
> 旧仓库 `llmrag`（Flask 单体原型）已冻结保留，本文档只记录新仓库的变化。

---

## 一、一页总览

| 维度 | 变化前（llmrag 原型） | 变化后（job-copilot） |
|---|---|---|
| 后端框架 | Flask + Injector + 4 套 config 文件 | FastAPI + pydantic-settings 单例 + Depends 注入 |
| 前端 | jQuery（index.html + 1545 行单文件 JS + 遗留死代码） | Vue 3 + Vite + Pinia + Element Plus 组件化工程 |
| 部署形态 | Flask dev server + 手工 Nginx | uvicorn/gunicorn + Docker Compose 三件套 + systemd 指南 |
| 接口 | 34 条（含 5 条死接口） | 34 条（`/api/v1` 前缀 + SSE 流式 + 删除会话） |
| 数据库 | 7 张表 | 7 张表 + knowledge_entries（共 8 张），schema 兼容 |
| 测试 | 4 个手工脚本式单测 | pytest 33 个用例（含回归测试）全绿 |
| 规模 | — | 后端 7077 行 Python / 前端 1578 行 / 150 个入库文件 / 17 commits |

**一句话**：核心服务层（检索/评分/面试/压缩/校验）原样迁移并保持行为兼容，Web 壳与前端彻底重写，过程中实锤并修复了旧系统 3 个潜伏 bug，新增 SSE 流式、知识库 AI 审核自主更新、内置技能包三项能力。

## 三、修复的旧系统问题（全部有实测证据）

| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| 1 | 文档上传接口必返 500（文档实际已 indexed，但简历版本从未创建） | `_create_resume_version` 先 `execute()`（自动开启事务）再显式 `begin()`，SQLAlchemy 2.0 必抛 InvalidRequestError | 单事务内读+写（P2） |
| 2 | 模拟面试过程数据从未持久化 | `answer()` 全部写库无提交，`session.close()` 整体回滚 | 读快照 → LLM 评估 → 单事务落库 三段式（P3） |
| 3 | 截图分析链路漏更新简历版本分数 | `image_handler.save_analysis` 与 `JobHandler._save_analysis` 重复实现且行为不一致 | 合并为 `job_analysis_store_service`（P3） |
| 4 | （自纠）技能描述花括号炸掉全部 agent 请求 | 动态目录注入 ChatPromptTemplate 未转义 `{简称}` 被当模板变量 | `build_agent_system_prompt()` 转义 + 模板安全回归测试（技能内置时） |

其他架构级修复：interview `total_score` Integer→Float；索引重建原子化（tmp+rename）；`tool.invoke` 异常转 ToolMessage；BGE reranker 懒加载缓存；MultiplyTool 参数校验；init_db errno 判断。

## 四、新增能力

1. **SSE 流式问答**：`meta → delta* → sources → verification → done`；无工具路径逐 token，工具路径整段下发；前端打字机 + 智能跟随（上翻不打扰）。
2. **知识库自主更新**：提交内容 / AI 自主生成 → AI 审核（面试相关性 + 查重 + 归类）→ 通过才入库并**增量**更新向量索引；fail-closed；拒绝留审计。
3. **知识库常驻补充**：从"三级兜底"改为始终追加 Top-2 相关条目进对话上下文——聊天问面试知识时 AI 结合知识库与自身知识作答（会话有简历时兜底模式永远轮不到知识库，这是策略性修正）。
4. **内置 ASu-skills 技能包**：9 个求职技能（job-match/great-resume/make-resume/interview/project-guide/evidence-recap/contributor/job-apply/offer），渐进式加载（清单进提示、`load_skill` 按需取全文）。
5. **幻觉风险分级升级**：无支撑断言含编造量化数据（百分比/小数/倍数/多位数字）→ 至少 medium；≥2 条或占比 ≥10% → high（全链路验证发现"编造 22.6% 召回率提升"仅判 low 后修复）。
6. **右键删除对话**：单事务级联清 6 张表 + 文件 + 向量索引；前端右键菜单 + 确认 + 当前会话状态联动清空。
7. **一键启动**：`start.bat`/`stop.bat`（Windows 双击）、`start.sh`/`stop.sh`（Git Bash/Linux），自动装依赖、就绪检查、开浏览器。
8. **前端布局**：输入卡片悬浮钉底、面板区限高滚动（后整删）、长对话滚轮修复（grid 行高根因）、回到底部按钮、markdown 渲染 + 引用角标 + 来源面板 + 幻觉徽标。

## 六、遗留事项

1. **阈值检索层失效**（P2）：text-embedding-v3 未归一化导致 0.35 阈值恒空，精度层退化为兜底层 → `normalize_L2` 或余弦 relevance_fn + 重新标定。
2. **数据库隔离**：仍在共享远程 `llmrag` 库，建独立 `job_copilot` 库只需管理员两条 SQL + 改一行 .env。
3. **幻觉校验的"真但无据"误伤**：上下文校验按"是否有上下文支撑"判定，事实为真但简历未写的内容（如 GitHub 链接）会被标无支撑——语义如此，如需优化可把 GitHub 等元数据并入证据源。
4. **知识库审核为单次 LLM 判定**：误放行增多时可加低置信度人工复核队列。
5. **旧仓库收尾**：`llmrag` 冻结；其面试文档中的代码行号需指向新仓库更新；README/简历表述切换。
6. **前端 bundle 2.3MB**（已删 echarts 后应明显变小，未重新度量）：可做 code-split。
